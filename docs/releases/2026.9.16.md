# 2026.9.16

_Released 2026-10-01 · [compare 2026.9.14…2026.9.16](https://github.com/perosb/qvantum_custom_component/compare/2026.9.14...2026.9.16) · [all releases](https://github.com/perosb/qvantum_custom_component/tree/main/docs/releases)_

A reliability-focused release. The cloud transport is hardened end to end — a real
reauth flow, one error contract across reads and writes, serialized token refresh
and proper 429 handling — while a batch of Modbus-only diagnostics lands (alarm
sensors, display firmware, a heating-curve advisor and a ventilation-filter
calendar). Config-entry diagnostics, DHW device triggers and wider DHW start/stop
limits round it out.

## More alarm and hot-water automations

You can monitor active alarms and use new automations for shower flow, a low hot-water tank, and extra hot water finishing. The low-tank automation is available in local mode when the relevant reading is present.

_Related: [#233](https://github.com/perosb/qvantum_custom_component/pull/233), [#262](https://github.com/perosb/qvantum_custom_component/pull/262)_

## More flexible hot-water controls

The hot-water start and stop temperatures can now be set across a wider range while keeping the start temperature below the stop temperature. Extra hot-water actions also work with local device IDs, and hot-water capacity requests are checked consistently.

_Related: [#234](https://github.com/perosb/qvantum_custom_component/pull/234), [#241](https://github.com/perosb/qvantum_custom_component/pull/241), [#270](https://github.com/perosb/qvantum_custom_component/pull/270)_

## Climate and sensor improvements

Climate controls work correctly when no indoor sensor is selected, and cooling is reported accurately. Temperature displays respect unit conversions, and the tap-water timer uses the correct timestamp format.

_Related: [#239](https://github.com/perosb/qvantum_custom_component/pull/239), [#240](https://github.com/perosb/qvantum_custom_component/pull/240), [#256](https://github.com/perosb/qvantum_custom_component/pull/256)_

## More reliable cloud connections

Cloud sign-in problems can prompt you to update your credentials, while temporary server errors and rate limits are handled without unnecessary repeated sign-ins. Failed updates are reported more clearly, and the integration keeps known settings when an unexpected response arrives.

_Related: [#238](https://github.com/perosb/qvantum_custom_component/pull/238), [#243](https://github.com/perosb/qvantum_custom_component/pull/243), [#249](https://github.com/perosb/qvantum_custom_component/pull/249), [#251](https://github.com/perosb/qvantum_custom_component/pull/251), [#267](https://github.com/perosb/qvantum_custom_component/pull/267), [#268](https://github.com/perosb/qvantum_custom_component/pull/268), [#272](https://github.com/perosb/qvantum_custom_component/pull/272)_

## More up-to-date firmware information

Firmware versions now appear on the Home Assistant device page after a maintenance check, without needing to reload the integration. Local mode also has a display firmware sensor that refreshes periodically and updates when the version changes.

_Related: [#254](https://github.com/perosb/qvantum_custom_component/pull/254), [#255](https://github.com/perosb/qvantum_custom_component/pull/255)_

## Heating advice and filter calendar in local mode

A new heating-curve advisor offers guidance based on recent room-temperature readings; it does not change settings automatically. A read-only calendar shows the estimated ventilation-filter due date and keeps it steady across restarts.

_Related: [#263](https://github.com/perosb/qvantum_custom_component/pull/263), [#264](https://github.com/perosb/qvantum_custom_component/pull/264)_

## Safer diagnostic information

Diagnostic downloads now omit credentials and redact device serial identifiers, including in device details and metric lists. Diagnostics can still be generated when some integration data is unavailable.

_Related: [#259](https://github.com/perosb/qvantum_custom_component/pull/259), [#265](https://github.com/perosb/qvantum_custom_component/pull/265)_

## More complete translations

Translations now include missing hot-water names and modes, and translation entries are checked against the English set to catch gaps and mismatches.

_Related: [#236](https://github.com/perosb/qvantum_custom_component/pull/236)_

## Quieter, more efficient updates

The integration reuses its list of enabled readings until entities or devices change, reducing repeated checks. Warnings about readings the cloud service does not provide are shown once per session instead of on every update.

_Related: [#250](https://github.com/perosb/qvantum_custom_component/pull/250), [#257](https://github.com/perosb/qvantum_custom_component/pull/257)_

_Internal changes (refactor / tests / CI / docs), not described in detail: #235, #237, #244, #245, #246, #247, #248, #253, #258, #260, #261, #269, #271, #273._

> [!IMPORTANT]
> Setup is **Cloud HTTP** or **local Modbus**.
> Local Modbus is read-only until writing is enabled.
> SmartControl stay cloud-only.


> [!WARNING]
> **Modbus mode**
> Enabling Modbus writing means you accept full responsibility for values written to the pump.
> Incorrect or out-of-range values may void the warranty and/or affect lifecycle and performance.


> [!WARNING]
> **Cloud mode**
> Elevate access assigns "Remote Service" (service tech) rights to your user. Cloud HTTP only.
> Cloud mode uses the same internal API as the app. Use at your own risk ;)
