# 2026.11.10

_Released 2026-11-20 · [compare 2026.11.8…2026.11.10](https://github.com/perosb/qvantum_custom_component/compare/2026.11.8...2026.11.10) · [all releases](https://github.com/perosb/qvantum_custom_component/tree/main/docs/releases)_

The guides now explain what the adaptive heating curve does, when it is ready, what it can affect, how to stop it, and where to get help; they also clarify the health rating. The curve now gives a room-temperature verdict—reduce, ok or increase—shows it on the card, and can run with accounts that have write access using the heat pump’s own temperature limits. More heat-pump readings, the filter calendar and the heating-load estimate are now available across supported connection types, and standing-loss results show how much evidence supports them. Fixes return control of the curve when changing to a connection that cannot manage it, remove a misleading hot-water-capacity warning, and show rejected or not-yet-measured results as unavailable rather than as real measurements.

## Clearer adaptive heating-curve advice

A new verdict recommends whether to reduce, keep, or increase the heating curve based on a full day of room-temperature results. The dashboard now puts this advice first and shows supporting details when available.

_Related: [#523](https://github.com/perosb/qvantum_custom_component/pull/523), [#533](https://github.com/perosb/qvantum_custom_component/pull/533)_

## Adaptive heating curves across connection types

Adaptive heating curves can now work with cloud-connected pumps as well as locally connected pumps, using the pump’s own supply-temperature limits and available heating-load data. When switching away from a connection that cannot continue managing an active curve, the integration makes a best-effort attempt to return control to the pump.

_Related: [#525](https://github.com/perosb/qvantum_custom_component/pull/525), [#527](https://github.com/perosb/qvantum_custom_component/pull/527), [#535](https://github.com/perosb/qvantum_custom_component/pull/535), [#538](https://github.com/perosb/qvantum_custom_component/pull/538)_

## More pump data and filter-calendar support

Cloud-connected pumps can now provide compressor and fan lifetime figures, filter time remaining, and the data needed for the filter calendar. This also enables compressor cycling information used in the pump’s health assessment.

_Related: [#536](https://github.com/perosb/qvantum_custom_component/pull/536), [#537](https://github.com/perosb/qvantum_custom_component/pull/537)_

## More context for hot-water loss estimates

Hot-water standing-loss estimates now include how many accepted observations and hours of data support them, and this information is retained after a restart. Before any observations are accepted, the evidence is shown as unavailable rather than as zero.

_Related: [#529](https://github.com/perosb/qvantum_custom_component/pull/529), [#530](https://github.com/perosb/qvantum_custom_component/pull/530)_

## Fewer confusing hot-water capacity warnings

The integration no longer warns when its own hot-water capacity label differs from the label reported by the pump’s app. It still reports a warning when a temperature pair does not match a known capacity.

_Related: [#528](https://github.com/perosb/qvantum_custom_component/pull/528)_

## More reliable room-compensation diagnostics

A room-compensation result rejected as noise is no longer presented as a measured value. The applied correction remains unchanged.

_Related: [#531](https://github.com/perosb/qvantum_custom_component/pull/531)_

_Internal changes (refactor / tests / CI / docs), not described in detail: #519, #520, #521, #524, #526, #532, #534._

> [!IMPORTANT]
> Setup is **Cloud HTTP** or **local Modbus**.
> Local Modbus is read-only until writing is enabled.
> SmartControl stay cloud-only.


> [!WARNING]
> **Modbus mode**
> Enabling Modbus writing means you accept full responsibility for values written to the pump.
> Incorrect or out-of-range values may void the warranty and/or affect lifecycle and performance.


> [!WARNING]
> **Cloud mode**
> Elevate access assigns "Remote Service" (service tech) rights to your user. Cloud HTTP only.
> Cloud mode uses the same internal API as the app. Use at your own risk ;)
