# 2026.11.1

_Released 2026-11-04 · [compare 2026.10.22…2026.11.1](https://github.com/perosb/qvantum_custom_component/compare/2026.10.22...2026.11.1) · [all releases](https://github.com/perosb/qvantum_custom_component/tree/main/docs/releases)_

Solar adjustments now fall back to hourly estimates when a day-based estimate isn’t usable, and weak hourly estimates are no longer applied. Wind adjustments now require cold, windy weather on enough separate days, not just enough total hours. Temperature controls are updated for newer Home Assistant versions, and the defrost indicator is renamed “Defrost needed” because it signals a request, not a countdown or confirmed defrost; existing automations continue to work.

## More reliable solar estimates

Solar adjustments are now used only when there is enough evidence to support them. Estimates with weak evidence remain visible for reference but no longer affect the result.

_Related: [#469](https://github.com/perosb/qvantum_custom_component/pull/469)_

## More reliable wind estimates

Wind adjustments now require evidence across enough cold, windy days, as well as enough qualifying hours. You can see both evidence counts and which requirement was not met.

_Related: [#470](https://github.com/perosb/qvantum_custom_component/pull/470)_

## Compatibility with newer Home Assistant versions

Temperature entities now use the interface expected by newer Home Assistant versions, avoiding deprecation warnings while preserving compatibility with supported older versions.

_Related: [#471](https://github.com/perosb/qvantum_custom_component/pull/471)_

## Clearer defrost wording

The defrost indicator is now called “Defrost needed,” reflecting that it signals a request rather than a countdown. Automation triggers and conditions use clearer wording, and existing automations continue to work.

_Related: [#472](https://github.com/perosb/qvantum_custom_component/pull/472)_

_Internal changes (refactor / tests / CI / docs), not described in detail: #468, #473._

> [!IMPORTANT]
> Setup is **Cloud HTTP** or **local Modbus**.
> Local Modbus is read-only until writing is enabled.
> SmartControl stay cloud-only.


> [!WARNING]
> **Modbus mode**
> Enabling Modbus writing means you accept full responsibility for values written to the pump.
> Incorrect or out-of-range values may void the warranty and/or affect lifecycle and performance.


> [!WARNING]
> **Cloud mode**
> Elevate access assigns "Remote Service" (service tech) rights to your user. Cloud HTTP only.
> Cloud mode uses the same internal API as the app. Use at your own risk ;)
