# 2026.10.20

_Released 2026-10-25 · [compare 2026.10.18…2026.10.20](https://github.com/perosb/qvantum_custom_component/compare/2026.10.18...2026.10.20) · [all releases](https://github.com/perosb/qvantum_custom_component/tree/main/docs/releases)_

Highlights: Hot-water capacity notices now describe the pump’s actual start and stop temperatures, no longer suggest choosing a preset that may not exist, and stay quiet when Home Assistant can’t change the pump. Shower estimates are now named for what they show: remaining shower minutes and showers remaining; existing entity IDs are unchanged. The heating curve uses steadier heating data and updates only the points relevant to the forecast, reducing unnecessary changes while keeping the curve in order.

## Hot-water capacity messages reflect the temperatures the pump uses

Capacity messages now show the pump’s actual hot-water start and stop temperatures without suggesting that you choose a level that may not be available. Separate messages distinguish an unrecognised temperature pair from a disagreement between the pair and a reported level.

_Related: [#441](https://github.com/perosb/qvantum_custom_component/pull/441), [#447](https://github.com/perosb/qvantum_custom_component/pull/447)_

## Capacity messages are clearer and quieter on read-only connections

The messages now explain that the pump is using an unknown preset, without pointing you toward a possibly outdated level. They are not raised on read-only connections, where Home Assistant cannot change the pump’s settings.

_Related: [#451](https://github.com/perosb/qvantum_custom_component/pull/451)_

## Shower estimates have clearer names

The estimate of time until shower water cools to 38 °C is now called “Remaining shower minutes,” and the estimated number of showers is called “Showers remaining.” Existing installations keep their entity IDs, so existing automations and dashboards continue to work.

_Related: [#446](https://github.com/perosb/qvantum_custom_component/pull/446)_

## Heating adjustments use a steadier power estimate

The adaptive heating adjustment now uses power measured across compressor cycles rather than relying on a single reading. This helps avoid erratic adjustments when the heat pump cycles on and off, and waits for enough observed data before using the estimate.

_Related: [#448](https://github.com/perosb/qvantum_custom_component/pull/448)_

## Adaptive curve updates focus on relevant points

The heating curve now updates points that are relevant to the weather forecast and avoids small, repeated changes. It also keeps the resulting curve in a valid order and respects the heat pump’s limits.

_Related: [#449](https://github.com/perosb/qvantum_custom_component/pull/449)_

_Internal changes (refactor / tests / CI / docs), not described in detail: #442, #443, #444, #445._

> [!IMPORTANT]
> Setup is **Cloud HTTP** or **local Modbus**.
> Local Modbus is read-only until writing is enabled.
> SmartControl stay cloud-only.


> [!WARNING]
> **Modbus mode**
> Enabling Modbus writing means you accept full responsibility for values written to the pump.
> Incorrect or out-of-range values may void the warranty and/or affect lifecycle and performance.


> [!WARNING]
> **Cloud mode**
> Elevate access assigns "Remote Service" (service tech) rights to your user. Cloud HTTP only.
> Cloud mode uses the same internal API as the app. Use at your own risk ;)
