# 2026.10.4

_Released 2026-10-13 · [compare 2026.10.3…2026.10.4](https://github.com/perosb/qvantum_custom_component/compare/2026.10.3...2026.10.4) · [all releases](https://github.com/perosb/qvantum_custom_component/tree/main/docs/releases)_

Sensor identities stay stable when Home Assistant changes how it describes the device, so affected efficiency and curve sensors are not recreated. Adaptive-curve readiness now accounts for room compensation, so room-temperature changes no longer keep it from becoming ready; this adjustment is used only when there is enough information to identify it.

## New features

### write release highlights into the release before publishing ([#338](https://github.com/perosb/qvantum_custom_component/pull/338))

New workflow **Release highlights** (`workflow_dispatch`, input `tag`): writes the polished end-user overview into the release body for that tag — draft or published — so the release email GitHub sends on publish already contains the highlights. It inserts the overview only (no changelog link) and touches nothing else. New generator mode `--highlights-only`: resolves the release (drafts work — `gh release view`/`edit` accept a draft tag), builds the overview via OpenRouter, and calls `update_release_notes(..., link=False)`. Re-running reuses the overview already in the body (no extra model call). The normal publish run now reuses an overview already present in the release body before generating a new one, so the email highlights, the notes file and the final body stay identical. `update_release_notes` gains `link=False` and compares the rebuilt body before editing (idempotent). Zip and notes creation are unchanged.

## Bug fixes

### resolve device id without requiring DeviceInfo to be a dict ([#340](https://github.com/perosb/qvantum_custom_component/pull/340))

Keeps every entity's unique id stable when Home Assistant stops representing `DeviceInfo` as a plain dict. Affects cloud and Modbus alike. `resolve_device_id` now reads the device id from `DeviceInfo` as an attribute when it is not a mapping, and keeps the mapping path for the coordinator's raw device dict. Fixes the efficiency, curve and efficiency-binary sensors, whose unique ids would otherwise end in `_None` and be recreated as new entities after home-assistant/core#180251.

### drop the pump's room term from adaptive-curve readiness ([#342](https://github.com/perosb/qvantum_custom_component/pull/342))

The adaptive-curve `ready` signal compares the shadow curve with the pump's `cal_heat_temp`. While the pump runs room compensation (BT2 or an external room sensor) that signal carries a room term the shadow curve deliberately does not emit, so the median deviation tracked the daily room swing and stayed above 1 °C — `ready` could never become true, no matter how long it ran. The coordinator now identifies the pump's room-compensation gain from the same Auto hours it uses to learn the baseline (residual fitted against outdoor and indoor − target), persists it, and removes `gain × (indoor − target)` from the deviation before it feeds the readiness window. The gain is exposed as `room_gain_c_per_c` on `sensor.qvantum_adaptive_curve_deviation`; no correction is applied while it is unidentified (no room sensor, or too little room-error spread to fit). No change to what the curve writes or to the shadow points — only the readiness measurement.
