# 2026.10.13

_Released 2026-10-24 · [compare 2026.10.12…2026.10.13](https://github.com/perosb/qvantum_custom_component/compare/2026.10.12...2026.10.13) · [all releases](https://github.com/perosb/qvantum_custom_component/tree/main/docs/releases)_

The integration now recognizes when an indoor temperature reading is just a placeholder, so it no longer skews the room temperature or the estimate of heat lost from the hot-water tank. It also keeps that reading out of home heat-loss, thermal-mass, solar, and heating-curve calculations. Where possible, it uses another suitable temperature reading; otherwise, it avoids using the unreliable data.

## Missing room sensors no longer distort heat-pump readings

When an interior sensor is absent, its placeholder reading is no longer mistaken for a real temperature. This keeps room readings, hot-water loss estimates and performance statistics from being skewed by the missing sensor.

_Related: [#424](https://github.com/perosb/qvantum_custom_component/pull/424), [#425](https://github.com/perosb/qvantum_custom_component/pull/425), [#426](https://github.com/perosb/qvantum_custom_component/pull/426)_

> [!IMPORTANT]
> Setup is **Cloud HTTP** or **local Modbus**.
> Local Modbus is read-only until writing is enabled.
> SmartControl stay cloud-only.


> [!WARNING]
> **Modbus mode**
> Enabling Modbus writing means you accept full responsibility for values written to the pump.
> Incorrect or out-of-range values may void the warranty and/or affect lifecycle and performance.


> [!WARNING]
> **Cloud mode**
> Elevate access assigns "Remote Service" (service tech) rights to your user. Cloud HTTP only.
> Cloud mode uses the same internal API as the app. Use at your own risk ;)
