# 2026.10.5

_Released 2026-10-13 · [compare 2026.10.3…2026.10.5](https://github.com/perosb/qvantum_custom_component/compare/2026.10.3...2026.10.5) · [all releases](https://github.com/perosb/qvantum_custom_component/tree/main/docs/releases)_

Your external room-temperature reading is now available as a sensor and can be used by the integration’s temperature and efficiency tracking; entity names also remain stable across Home Assistant changes. Adaptive-curve readiness now accounts for room compensation and heating periods, so occasional temperature swings are less likely to prevent it from becoming ready.

## Release highlights are included before publication

Release highlights can now be added before a release is published, so the release email and notes show the same overview.

_Related: [#338](https://github.com/perosb/qvantum_custom_component/pull/338)_

## Existing entities keep their identity

Sensors keep their existing identities even when Home Assistant changes how it represents device information, helping prevent duplicate entities.

_Related: [#340](https://github.com/perosb/qvantum_custom_component/pull/340)_

## Adaptive curve readiness accounts for room compensation

The adaptive curve’s readiness check now accounts for room-temperature compensation, so room-related changes are less likely to prevent it from becoming ready.

_Related: [#342](https://github.com/perosb/qvantum_custom_component/pull/342)_

## Adaptive curve readiness uses a more practical comparison

The readiness check now compares the learned heating baseline with the pump’s behavior during heating hours. It allows for occasional outliers and requires enough heating data before reporting readiness.

_Related: [#343](https://github.com/perosb/qvantum_custom_component/pull/343)_

## External room temperature is available for tracking

When an external room sensor is used, its temperature is now recorded as a sensor value as well as being available to control the pump. This lets temperature-based features use the same room reading as the pump.

_Related: [#344](https://github.com/perosb/qvantum_custom_component/pull/344)_

_Internal changes (refactor / tests / CI / docs), not described in detail: #336, #337, #341, #345._

> [!IMPORTANT]
> Setup is **Cloud HTTP** or **local Modbus**.
> Local Modbus is read-only until writing is enabled.
> SmartControl stay cloud-only.


> [!WARNING]
> **Modbus mode**
> Enabling Modbus writing means you accept full responsibility for values written to the pump.
> Incorrect or out-of-range values may void the warranty and/or affect lifecycle and performance.


> [!WARNING]
> **Cloud mode**
> Elevate access assigns "Remote Service" (service tech) rights to your user. Cloud HTTP only.
> Cloud mode uses the same internal API as the app. Use at your own risk ;)
